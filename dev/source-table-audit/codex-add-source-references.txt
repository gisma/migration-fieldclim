Core rules:
1. Documentation only. Do not change any numeric value, formula, default argument, warning, guard or return value.
2. Add or refine roxygen `@references` and short `@details` text where useful.
3. Do not claim full independent source validation.
4. Do not claim one-to-one table validation unless the source summary explicitly says the table was found.
5. Use generic but honest wording such as "based on", "uses values consistent with", "method background", or "package-specific implementation".
6. Where only the method family is supported, cite it as method background, not as exact source of the implemented values.
7. Where a package-specific shortcut remains unresolved, document that explicitly and neutrally.
8. Keep wording compact. Do not turn function help pages into long audit reports.
9. Run `devtools::document()`, then `devtools::test()`, then `devtools::check()`.
